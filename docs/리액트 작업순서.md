# 리액트(React) 작업순서 — SignSense FastAPI 서버 연동 가이드

목적
- React(브라우저) 클라이언트에서 SignSense FastAPI 서버로 WebRTC(DataChannel)를 사용해 카메라 프레임을 전송하고, 서버의 추론 결과를 받아 처리하는 구체적인 작업 순서를 제공합니다.
- HTTPS/WSS 환경에서의 로컬 개발(인증서 사용) 방법과 내부 저장 엔드포인트(`save-learning`, `save-quiz`)의 호출/설계 주의사항도 포함합니다.

대상 독자
- 프론트엔드(React) 개발자, 클라이언트-서버 연동을 담당하는 개발자

전제 조건
- 서버가 HTTPS(SSL)로 실행되어야 함(wss 사용). 로컬에서는 `mkcert` 등으로 신뢰된 인증서를 만들고 `uvicorn --ssl-*` 옵션으로 실행하세요.
- 서버 엔드포인트: 시그널링 WebSocket `wss://<host>:<port>/ws/{session}`
- DataChannel label: `frames`
- 내부 저장 엔드포인트(`/api/internal/save-learning`, `/api/internal/save-quiz`)는 기본적으로 내부/신뢰된 호출용입니다. 브라우저에서 직접 호출하는 것은 권장하지 않습니다(보안상 이유).

요약 플로우
1. React 앱에서 시그널링 WebSocket(wss://.../ws/session-id) 연결
2. RTCPeerConnection 생성, DataChannel('frames') 생성 및 이벤트 바인딩
3. Offer 생성 → 시그널링 WS로 전송
4. 서버로부터 Answer 수신 → setRemoteDescription
5. DataChannel open 시점부터 캡처한 JPEG/바이너리 프레임(또는 chunked binary)을 전송
6. 필요 시 시그널링 WS로 `{ action: 'meta', meta: {...} }` 와 `{ action: 'flush' }` 메시지를 보내 메타데이터 전송 및 추론/저장 트리거
7. 서버가 `{ action: 'inference_result', result: {...} }` 메시지를 시그널링 WS로 전송하면 UI 업데이트

세부 단계(작업 순서)

1) 준비(서버와 인증서)
- 로컬 HTTPS 추천: `mkcert`로 로컬 인증서 생성 후 `uvicorn`에 `--ssl-keyfile`/`--ssl-certfile` 옵션으로 실행합니다.

예 (mkcert)
```
mkcert -install
mkcert localhost 127.0.0.1 ::1
```
uvicorn 실행(Windows 예)
```
uvicorn main:app --host 0.0.0.0 --port 8443 --ssl-keyfile certs\localhost-key.pem --ssl-certfile certs\localhost.pem --reload
```

2) 세션 ID 설계
- 세션 ID는 클라이언트가 생성하거나 서버가 발급할 수 있습니다. (예: UUID 또는 유저+타임스탬프 조합)
- 예시: `session-<userId>-<timestamp>` 또는 `uuidv4()`

3) React: 시그널링 WebSocket 연결
- WebSocket URL: `wss://<host>:<port>/ws/{sessionId}`
- 시그널링 WebSocket은 Offer/Answer와 기타 제어 메시지(`meta`, `flush`, `inference_result`)를 주고 받는 채널입니다.

예시 (간단한 WS 연결)
```javascript
const sessionId = 'session-123';
const ws = new WebSocket(`wss://localhost:8443/ws/${sessionId}`);
ws.onopen = () => console.log('signaling WS open');
ws.onmessage = (ev) => { const msg = JSON.parse(ev.data); /* handle */ };
```

4) RTCPeerConnection과 DataChannel 생성
- `pc.createDataChannel('frames')`로 데이터채널 생성
- `onopen`, `onmessage` 이벤트 바인딩
- (선택) 미리보기용으로 로컬 비디오 트랙을 `pc.addTrack(stream.getTracks()[0], stream)`로 추가

코드 예
```javascript
const pc = new RTCPeerConnection();
const dc = pc.createDataChannel('frames');
dc.binaryType = 'arraybuffer';

dc.onopen = () => console.log('DataChannel open');
dc.onmessage = (ev) => console.log('DC message', ev.data);

pc.onicecandidate = ({candidate}) => {
  // 간단 구현: ICE 후보를 따로 전송하지 않는다면 무시 가능합니다
};
```

5) Offer 생성 및 시그널링 전송
- Offer 생성: `const offer = await pc.createOffer(); await pc.setLocalDescription(offer);`
- Offer를 WS로 전송: `{ action: 'offer', type: offer.type, sdp: offer.sdp }`
- 서버는 Answer를 만들어 WS로 응답합니다. 수신 시 `pc.setRemoteDescription(answer)` 호출

6) 캡처한 프레임 전송(Blob → ArrayBuffer)
- 캡처 방법: <video>에서 canvas로 그린 뒤 `canvas.toBlob()` 사용
- Blob을 `await blob.arrayBuffer()`로 변환하여 `dc.send(arrayBuffer)`로 전송
- 프레임 크기/품질: JPEG quality 0.6~0.8 권장, 전송 FPS 20~25 권장

예시 (일회성 전송 함수)
```javascript
async function sendCanvasFrame(dc, canvas, quality=0.7) {
  return new Promise((resolve) => {
    canvas.toBlob(async (blob) => {
      const ab = await blob.arrayBuffer();
      dc.send(ab);
      resolve();
    }, 'image/jpeg', quality);
  });
}
```

프레임 연속 전송(쓰로틀링)
- setInterval 또는 requestAnimationFrame을 사용하되 전송률을 제한하세요.
- 장시간(프레임 수가 많은 경우)에는 서버의 `SIGN_SEQUENCE_TARGET_FRAMES` 제한을 확인하고, 초과하지 않도록 클라이언트에서 제어해야 합니다.

7) 메타데이터 전송 (선택)
- 서버에 단어/유저 메타를 미리 알려야 하는 경우, 시그널링 WS로 `{ action: 'meta', meta: { user_id, word_pk, word_name, ... } }`을 보냅니다.
- 서버는 이 메타를 내부 Collector에 저장하거나, 이후 `flush` 시점에 저장 로직과 함께 사용합니다.

8) Flush(추론/저장 트리거)
- 클라이언트가 더 이상 프레임을 보내지 않을 시점(또는 즉시 추론을 요청할 때) WS로 `{ action: 'flush' }` 전송
- 서버는 `flush` 메시지를 받아 현재 수집된 시퀀스로 추론을 실행하고, 내부 저장 엔드포인트를 백그라운드로 호출해 데이터 저장을 스케줄하거나 실행합니다.

9) 서버에서의 응답 처리
- 서버는 추론 완료 시 시그널링 WS로 `{ action: 'inference_result', result: { label, score, ... } }` 메시지를 클라이언트에 전송합니다.
- 클라이언트는 이 메시지를 받아 UI에 결과 표시 및 사용자 피드백을 진행합니다.

10) 내부 저장 엔드포인트 호출 방식(주의)
- `/api/internal/save-learning` 및 `/api/internal/save-quiz`는 보통 서버 내부에서 호출하거나, 신뢰된 백엔드(예: 회사의 API 게이트웨이)에서 호출하는 것이 안전합니다.
- 브라우저에서 직접 호출하면 인증 토큰(예: `INTERNAL_API_TOKEN`)이 노출될 위험이 있으므로 권장하지 않습니다.

내부 호출(서버 → 저장 모듈) 예시(서버 내부 동작 요약)
- WebRTC 핸들러에서 추론 후 `storage.save_learning(...)` 또는 `storage.save_quiz(...)`를 호출하거나, 내부 POST를 통해 백그라운드 작업으로 스케줄합니다.

브라우저에서 내부 엔드포인트를 테스트해야 한다면(테스트용), 다음 예를 참고하세요(보안 경고: 토큰을 브라우저에 두지 마세요)
```javascript
await fetch('https://localhost:8443/api/internal/save-quiz', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer <INTERNAL_API_TOKEN>'
  },
  body: JSON.stringify({ session_id: 'session-123', meta: { user_id: 'u1', word_pk: 1, word_name: '안녕' } })
});
```

11) 예제: React Hook 형태(간단)
- 아래 코드는 완전한 컴포넌트가 아니라 핵심 로직만 발췌한 예시입니다. 프로젝트 구조에 맞게 에러 처리, 상태관리(useState/useRef) 등을 추가하세요.

```javascript
// useSignSense.js (핵심 로직)
import { useRef, useEffect } from 'react';

export function useSignSense(sessionId) {
  const pcRef = useRef(null);
  const dcRef = useRef(null);
  const wsRef = useRef(null);

  useEffect(() => {
    const pc = new RTCPeerConnection();
    pcRef.current = pc;
    const dc = pc.createDataChannel('frames');
    dc.binaryType = 'arraybuffer';
    dc.onopen = () => console.log('DC open');
    dc.onmessage = (ev) => console.log('DC msg', ev.data);
    dcRef.current = dc;

    const ws = new WebSocket(`wss://localhost:8443/ws/${sessionId}`);
    wsRef.current = ws;
    ws.onmessage = async (ev) => {
      const msg = JSON.parse(ev.data);
      if (msg.type === 'answer') {
        await pc.setRemoteDescription(msg);
      } else if (msg.action === 'inference_result') {
        // handle
        console.log('inference', msg.result);
      }
    };

    (async () => {
      const offer = await pc.createOffer();
      await pc.setLocalDescription(offer);
      ws.onopen = () => {
        ws.send(JSON.stringify({ action: 'offer', type: offer.type, sdp: offer.sdp }));
      };
    })();

    return () => {
      dc.close();
      pc.close();
      ws.close();
    };
  }, [sessionId]);

  const sendFrame = async (canvas) => {
    if (!dcRef.current || dcRef.current.readyState !== 'open') return;
    const blob = await new Promise((res) => canvas.toBlob(res, 'image/jpeg', 0.7));
    const ab = await blob.arrayBuffer();
    dcRef.current.send(ab);
  };

  const sendMeta = (meta) => wsRef.current?.send(JSON.stringify({ action: 'meta', meta }));
  const flush = () => wsRef.current?.send(JSON.stringify({ action: 'flush' }));

  return { sendFrame, sendMeta, flush };
}
```

12) 디버깅 팁
- DataChannel이 열리지 않으면 Offer/Answer 교환과 ICE 상태를 확인하세요.
- 브라우저 콘솔에서 Mixed content(HTTPS 페이지에서 WS(wss) 아닌 ws 사용)의 경고를 확인하세요.
- 카메라 권한 문제: HTTPS에서만 getUserMedia가 동작하는지 확인
- 프레임이 서버로 전달되지 않으면 프레임 크기(Blob 용량)가 너무 크지 않은지, 또는 네트워크가 끊기지 않았는지 확인

보안 및 운영 주의사항
- 내부 저장 엔드포인트는 인증 토큰으로 보호하세요(`INTERNAL_API_TOKEN`). 브라우저에 토큰을 노출하지 마세요.
- 운영 환경에서는 정식 SSL 인증서를 사용하고, TURN 서버를 도입해 P2P/서버 통신 실패를 대비하세요.
